# ADR 0170: App icon from an Icon Composer bundle, wired through XcodeGen

- Status: Accepted (code merged on main; status updated 2026-10-06)
- Date: 2026-09-30
- Owner: BR (Brand and app icon)

## Context

The app has no icon. The owner designed one in Icon Composer: `Starling.icon`, a bundle with `icon.json` and two SVG layers, one Liquid Glass group ("Overlap"), and light and dark fills. The app project is generated by XcodeGen from `App/project.yml` (ADR 0005), so the icon has to be wired there, not in a project file.

What Apple documents for Xcode 27 ("Creating your app icon using Icon Composer"):

- Add the `.icon` file to the Xcode project in the app target. The system renders every platform, appearance, and size from that one file, and Xcode generates fallback images for older OS releases at build time.
- In the target's General tab, the App Icon name must match the Icon Composer file name without the extension. That field is the `ASSETCATALOG_COMPILER_APPICON_NAME` build setting.
- An Icon Composer file replaces an `AppIcon` asset catalog; Xcode uses the `.icon` file instead.

XcodeGen learned `.icon` in 2.45.1 (changelog: "Added built in `.icon` folder support for IconComposer #1600"). The owner's Mac has 2.44.1; CI installs the latest from Homebrew (2.46.0 today).

## Decision

1. The bundle lives at `App/Resources/Starling.icon`, copied unchanged from `Starling_icon_v2.zip` except for the shadow change in ADR 0171.
2. `App/project.yml` lists it as its own source with `type: file` and `buildPhase: resources`, so 2.44.1 and 2.45.1+ produce the same project, and sets `ASSETCATALOG_COMPILER_APPICON_NAME: Starling`. Nothing else in that file changes.
3. No `Assets.xcassets` `AppIcon` set. The `.icon` file is the only source.

## Verification

- `xcodegen generate` with 2.44.1 and with 2.46.0: both add `Starling.icon` to the Resources phase (2.46.0 also tags it `lastKnownFileType = wrapper.icon`).
- `xcodebuild build -scheme Starling -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO` succeeds. actool runs with `--app-icon Starling`. The built `Starling.app` has `CFBundleIcons.CFBundlePrimaryIcon.CFBundleIconName = Starling`, and `assetutil --info Assets.car` lists an `IconImageStack` named `Starling` for light, dark, and tintable appearances, the `Starling/Overlap` icon group, both SVG layers as vectors, and 1024 px flattened fallbacks.

## Consequences

- Lane H owns `App/` and is restructuring `project.yml` (PR #15). This wiring is one isolated commit so the Orchestrator can re-apply it on top of H's version: one source entry and one build setting.
- The icon is edited in Icon Composer (Xcode > Open Developer Tool > Icon Composer), never by hand. After an edit, run `python3 docs/brand/tools/icon_previews.py` to re-render the previews and recheck the gap.
- Once every environment has XcodeGen 2.45.1 or later, the explicit `type` and `buildPhase` can go.
