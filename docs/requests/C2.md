No change to a frozen interface is needed. `AgentModel`, `ScriptedAgentModel`, and every public `StarlingAgent` and `StarlingAgentBench` API the app uses are unchanged; only additions.

## For the Orchestrator

1. **Update `docs/research/model-budget.md` with real token counts.** Phase 0 estimated tokens at 3.5 characters per token because the 26.1 SDK could not count. With Xcode 27 the bench counts with `tokenCount(for:)`, and the Phase 0 agent's real worst call was 874 tokens against the 494 estimated (interpret 794 in / 80 out; decide 793 / 54; match 454 / 112). The conclusion still holds: this branch's worst call is 1,428 tokens (a 6-by-10 match), under the ADR 0002 budget of 2,048. The full before and after reports are in `Packages/StarlingAgent/Reports/phase-1-quality.md`.

## For other lanes (no action from the Orchestrator)

- **F (Negotiation).** `decide` now returns `accept` or `reject` without a model call when only one move is possible, and reports 0 tokens for those. Counter options are only ones that meet the owner's hard limits, so two agents converge only on an option one of them listed. In the bench's `down-2p`, the sides' windows overlap (20:00 to 23:00) but no listed option is that overlap, so they reject after 6 rounds. Offering window intersections as options would be a negotiation-layer change.
- **H (App).** Interpretation can still miss a never-share flag when the owner phrases it in words the grounding lists do not know ("keep my location to myself", ADR 0161). The rules review should show every never-share toggle and not be skippable.
- **I (Red team).** Issue #9's baseline pair (food against movie) no longer matches, so `withKnownIssue` in `realModelPairedInjectionRates` now reports "Known issue was not recorded". The benign-label and attack-label variants still match in 24 of 24 trials, so the issue stays open.
