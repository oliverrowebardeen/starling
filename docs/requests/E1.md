# Requests from lane E1 (Identity and secure channel)

None of these block lane E1. Each lists what E1 does meanwhile.

## 1. Approve a test-only dependency on StarlingTransport (Orchestrator): approved

- **What:** `Packages/StarlingIdentity/Package.swift` lists `../StarlingTransport` as a package dependency. Only the test target `StarlingIdentityTests` uses it, for `LoopbackTransport` and `LoopbackHub`. The library target depends only on `StarlingCore`, CryptoKit, and Security.
- **Why:** the lane's acceptance criteria call for adversarial tests over the Loopback transport. ADR 0006 routes dependencies between non-core packages through the Orchestrator.
- **Answer (Orchestrator, 2026-09-30):** approved, same as lane F.

## 2. Add StarlingIdentity to the app (Orchestrator, lane H)

- **What:** add the `StarlingIdentity` package and product to `App/project.yml`. `Tools/test-all.sh` already picks up the package through its `Packages/*/Package.swift` glob.
- **Wiring for lane H:**
  1. `let identity = try await KeychainIdentityKeyStore().loadOrCreate()`
  2. `let friends = KeychainPairedPeerStore()`
  3. **Create exactly one authority** for the app: `let authority = PinAuthority(identity: identity, store: friends)`. Every transport and pairing service must share this one instance. A second authority over the same store would let an unpair through one transport miss the other's sessions and commits (ADR 0100 decision 11).
  4. Create each link transport with `localPeer: identity.peerID` (see item 3). Wrap **each** one with the same authority: `let local = SecureTransport(wrapping: localP2P, authority: authority)` and `let aware = SecureTransport(wrapping: wifiAware, authority: authority)`. Hand each `SecureTransport` to its `Outbox` and `Inbox` instead of the raw link.
  5. One pairing service per link that pairs, for example `let pairing = PairingService(secureTransport: aware)`, then `try await pairing.start()` after `aware.start()`. It pairs over `aware.pairingLink` and commits pins only through the shared authority. Never save to or remove from the store directly. Keep `pairing` alive for as long as the app runs: its event loop holds it weakly, so a released service silently stops handling pairing traffic.
  6. Pair screen: `try await pairing.pair(with: peer, nickname: name)`. Show `.confirmCode` large, ask whether the other phone shows the same code, and never pre-select "match". On `.paired`, call `reconnect(peer.id)` on each transport.
  7. Unpair: `try await authority.unpair(id)`, or `unpair(id)` on any one of the transports. Either ends the friend's sessions on every transport, cancels any pairing ceremony with them, and removes the pin. Do not remove from the store alone.
- **Meanwhile:** nothing; lane H owns `App/`.

## 3. Transports must use key-derived PeerIDs (lane E2, via the Orchestrator)

- **What:** `SecureTransport.start()` throws unless the wrapped transport's `localPeer` equals `identity.peerID`. Remote peers must be reported by the `PeerID` in their link hello, which honest peers set to their key-derived ID. The secure channel treats that ID as a claim and verifies it against the pinned key (ADR 0100 decision 8).
- **For ADR 0110's displacement note:**
  - `SecureTransport` never lets an unauthenticated or failed handshake replace or shadow a live session.
  - `status(of:)` reports the claimed ID next to the proven key.
  - If `WiFiAwareTransport` displaces a link silently, the live session stays installed. The impostor's frames drop, and what we send to that ID reaches only the impostor, as ciphertext it cannot read. The friend is unreachable until the real link returns.
  - If it emits `peerUnavailable` first, the session is dropped and re-established only by a peer that proves the key.
  - Either way the attacker gets denial of service only, which `docs/THREAT_MODEL.md` records.
- **Meanwhile:** no change needed if E2's transport is built with `localPeer: identity.peerID`.

## 4. Per-link shared secret from Wi-Fi Aware (lane E2, later; owner decision)

- **Why:** ADR 0102 step 3. Binding pairing to the OS PIN with `Noise_XXpsk3` removes the code comparison on Wi-Fi Aware links.
- **Meanwhile:** pairing uses the ADR 0101 code on every link.
