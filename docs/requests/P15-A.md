# Requests from lane P15-A (Shell and IA)

## 1. Confirm who reports consent events (lanes B to E)

**What.** The lifecycle coordinator, not skill services, reports `consentNeeded(request:)` and `consentGiven(request:)` (ADR 0201 decision 3). The app's `ConsentProvider` reads `Disclosure.conversation` when `Outbox` asks it, suspends that conversation's interaction under the next request ID above its watermark, and resumes it (or ends it declined) when the owner answers. Skill services should not emit consent events.

**Why.** A sheet appears inside `Outbox.send`, which the service cannot observe, and request IDs only rise, so two sources would collide: the second `consentNeeded` is refused as `UnknownConsentRequest`, or an interaction waits on a request nobody will close. Lane B's kickoff mentions "consent request IDs"; this asks the Orchestrator to confirm the split with lanes B, C, D, and E, as amendment 13 did for `.started`.

**Tests.** `ConsentLifecycleTests` and `AppOutboxTests.everySendIsRecordedOnItsInteraction`.

**Meanwhile.** Built this way. A service that emits consent events anyway gets them applied if their IDs happen to rise, or dropped and logged if not.

## 2. A Release check: no Developer section, no test-build notices

**What.** A CI step (and a `Tools/local-gate.sh` step) after the Release build, in the style of `Tools/check-release-no-fakes.sh`. Proposed `Tools/check-release-no-debug.sh`:

```bash
#!/usr/bin/env bash
# Fails if a Release build contains the Debug-only Developer section or a
# test-build notice (ADR 0015 decision 5, lane P15-A).
set -euo pipefail
root="$(cd "$(dirname "$0")/.." && pwd)"
derived="${1:-$root/.build/app-release}"
binary="$derived/Build/Products/Release-iphonesimulator/Starling.app/Starling"
symbols="$(nm "$binary")"
grep -q StarlingCore <<<"$symbols" || { echo "No StarlingCore symbols; cannot check."; exit 1; }
for name in DeveloperView DebugHarness DemoDriver LifecycleSelfTest DebugPermissionAccess; do
  if grep -q "$name" <<<"$symbols"; then echo "Release contains $name (ADR 0015)."; exit 1; fi
done
for text in "This is a test build" "doesn't hide free times" "scripted services"; do
  if strings "$binary" | grep -qF "$text"; then echo "Release contains the notice \"$text\" (ADR 0015)."; exit 1; fi
done
echo "Release has no Developer section and no test-build notices."
```

It reuses the Release build that `check-release-no-fakes.sh` already makes.

**Why.** ADR 0015 decision 5 and the lane plan's acceptance: Release builds have no Developer section and no test-build notices, guarded by CI. `Tools/` is the Orchestrator's.

**Meanwhile.** Every file in `App/Sources/Developer/` and the Debug composition sit inside `#if DEBUG`; Release passes `EmptyView()` as You's developer slot. I ran the script above by hand against this branch's Release build (result in the PR).

## 3. Skill lanes: what the shell needs from each package (B, C, D, E)

So each skill drops in by filling `AppServices.makeSkills` and `permissions`:

- **B (Down for…)**: a `SkillService` initializer that takes the app's `Outbox`, the paired-peer store, and the local `PeerID`; and the `SkillModel` from StarlingAgent. The shell uses the model's `proposalText` with its own template as fallback.
- **C (Find a time)**: a `PermissionAccess` for `.calendarFullAccess` (status and request), and the `NSCalendarsFullAccessUsageDescription` text for the Info.plist.
- **D (Pick a place)**: a `PermissionAccess` for `.locationWhenInUse` and the `NSLocationWhenInUseUsageDescription` text. The shell asks for location when the owner taps "Suggest places near me", not when Pick a place starts (ADR 0013 decision 2).
- **E (chaining)**: an `OutboxObserver` that records `EgressRecord`s; the shell's `EgressObserver` and `LifecycleCoordinator.recordEgress(_:conversation:)` are the interim. A time-triggered chain API for "Swap photos after" (the shell shows nothing for it while Swap photos is flagged off).

## 4. Descriptors in Release

`LiveServices.registry` repeats `SampleSkills`' descriptors so Release can show New's tiles and You's switches without linking StarlingFakes. When each skill package exports its descriptor, the shell switches to those. No action needed beyond lanes B to E exporting `descriptor`.
