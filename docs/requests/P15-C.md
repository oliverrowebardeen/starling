# Lane P15-C requests (Find a time)

Owner: Orchestrator. Consumers: P15-A (shell), P15-F (red team). Branch `phase-1.5/c-find-a-time`, rebased on Core v2.1 (`753ddcf`). Nothing here blocks P15-C. Items 3, 5, 6, 8, 9, and 10 were resolved in Core v2.1 (PR #57); item 7 is deferred to a later freeze.

## For P15-A: wiring Find a time

### 1. Calendar permission: the access API and the purpose string

What lane A calls from Starling's pre-permission sheet (ADR 0013, decision 3; ADR 0220):

```swift
import StarlingAvailability

let calendar = EventKitCalendarStore()          // one per app
let access = CalendarAccess(store: calendar)

access.status              // CalendarAccessStatus: .notDetermined, .fullAccess, .writeOnly, .denied, .restricted
access.shouldShowSheet     // true only when the system alert can still appear
await access.request()     // call only from the sheet's "Continue"; returns the new status
```

- When the owner starts Find a time and `shouldShowSheet` is true, show the sheet, then call `request()` from "Continue". On `.denied`, show `FindATimeCopy.deniedFallback` ("No problem, your agent will ask you instead.") and start the skill anyway: it asks the owner.
- When `shouldShowSheet` is false, start the skill without a sheet. It reads the calendar if it can and asks the owner otherwise.
- Nothing else may call `request()`. The service never does, so a friend's request never raises the alert.

**Info.plist** (lane A owns `App/`): add the key `CalendarAccess.usageDescriptionKey` (`NSCalendarsFullAccessUsageDescription`) with `CalendarAccess.purposeString`:

> Starling checks when you're busy so friends' agents can find a time without asking you. Event details stay on your iPhone.

Without this key iOS 17 and later deny the request without showing the alert. Do not add `NSCalendarsUsageDescription` (pre-iOS 17) or any write-only key: Add to Calendar uses `EKEventEditViewController` and needs neither (ADR 0018).

**You › Skills:** store a `CalendarUse` (`.useMyCalendar` or `.justAskMe`, labels `FindATimeCopy.useMyCalendar` and `.justAskMe`) and show the permission line from `access.status`.

### 2. Building the service

```swift
let findATime = FindATimeService(
    localPeer: identity.peerID,
    outbox: outbox,                                    // the app's single Outbox
    pairedPeers: pairedPeerStore,
    availability: .standard(
        calendar: calendar,
        use: { await settings.calendarUse },           // You › Skills
        stated: { [] }                                 // optional: free windows the owner already stated
    ),
    checkpoints: FileFindATimeCheckpoints(directory: applicationSupport.appending(path: "FindATime")),
    isTurnedOn: { await settings.isOn(.findATime) },
    standingRules: { await settings.standingRules.constraints }   // "no plans before 10"
)
```

The app's `Outbox` needs the persisted `SentSequenceStore` (Core v2.1), so numbers keep rising across a relaunch. Start Find a time with `SkillIntent(mode: .invite)`: its only mode, and the one Compose should show without a toggle. Every send names its interaction in `OutboundContext.interaction`, so the consent coordinator can use `Disclosure.interaction`.

Register `FindATimeSkill.descriptor` (not `SampleSkills.findATime`) in the registry. Feed it every `InboxEvent`, including `hello`s, because the policy needs each friend's card to know their model runs on-device. Call `restore(_:)` at launch before the first `handle(_:)`.

The proposal card's sentence: `FindATimeProposalWriter(model:localPeer:timeZone:nickname:).sentence(for:)`, which uses `SkillModel.proposalText` and falls back to a template.

### 3. The sheet's third line differs by role: resolved

ADR 0013 amendment 6 (Core v2.1) adopts it: "Only a few times you're free" when starting (`FindATimeCopy.PermissionSheet.seesValueWhenAsking`), "Only times you're both free" when answering (`.seesValueWhenAnswering`).

### 4. Who reports consent events: resolved

The Orchestrator ruled on 2026-10-01: the app's `ConsentProvider` applies `consentNeeded`, `consentGiven`, and on a decline the owner's pass; the service adds nothing for a decline. A policy denial reports `blockedByPrivacy`, only for the current step (ADR 0011, amendments 13 and 14). Find a time follows this, and the coordinator applies `.started` before `start`.

### 5. `planEnded`: resolved

ADR 0011 amendment 15: the coordinator applies it. Find a time no longer reports it; it only forgets the conversation when the plan's time passes.

### 5a. The coordinator must not lose updates

Find a time's test coordinator first read an interaction from a store actor, applied an event, and saved it, with awaits in between. Two events could interleave and one overwrite the other: a consent approval saved over a withdrawal left a withdrawn request negotiating. Lane A's coordinator should apply each event to its record without suspending between the read and the write (or serialize per interaction). `Packages/Skills/FindATime/Tests/FindATimeTests/Harness.swift` (`Coordinator`) shows one way.

## For the Orchestrator: Core and tools

### 6. Clearing consent requests that died with the app: resolved

`InteractionEvent.consentCancelled(request:)`, applied by the coordinator at launch before `restore(_:)` (ADR 0011, amendment 15). Find a time's tests do the same.

### 7. Per-skill state on `Interaction` (Core, nonblocking)

`Interaction` has no place for state only the skill knows, so Find a time keeps its own `FindATimeCheckpointStore` (ADR 0222). Proposed for a later freeze: `Interaction.skillState: Data?` (bounded, opaque, never sent) and `SkillEvent.checkpoint(InteractionID, Data)`, so the coordinator persists it with the record and every skill restores the same way. **Deferred** by the Orchestrator to a later freeze; Find a time keeps its checkpoint store.

### 8 to 10: resolved in Core v2.1

- The Release check now catches every Fakes module, `StarlingAvailabilityFakes` included.
- `SampleSkills.findATime` lists people and calendar details and declares Invite.
- `Outbox` numbers an envelope only once it is cleared, starts each conversation on a launch above the clock in milliseconds and the `SentSequenceStore`, so a relaunch never reuses a number (`RestoreTests.aRestartBeforeTheConfirmationsLeftIsNotAPlan` depends on it).

### 11. Threat model additions (open)

For `docs/THREAT_MODEL.md`:

- A starter shows each friend up to 16 times it is free; with a calendar, the gaps show busy time in the range (never why). A friend who keeps sending requests learns 16 answers per request, at most 4 open requests at a time. Private PSI would remove this. (ADR 0221)
- No free time, a policy refusal (a Never setting), a pass, and a declined consent sheet are the same `reject(noOverlap)` on the wire, with no sequence gap, when answering and when agreeing (`IndistinguishableTests`). Timing still shows whether a friend's agent answered alone (a calendar) or its owner did. (ADRs 0019, 0221)
- Calendar details stay Never by default and are still read on the phone to judge candidates; only yes or no to the starter's own times leaves. (ADR 0019)
- Find a time checkpoints hold candidate times, friends' answers, and peer IDs at rest, with complete file protection on iOS, until the interaction ends. (ADR 0222)
- Over an unauthenticated transport, a forged answer under a friend's ID is refused if it names a time that was not offered; the secure channel is what rejects the forgery itself.
