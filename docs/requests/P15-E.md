# Lane P15-E requests (Chaining and audit)

Owner: Orchestrator. Consumers: lane A (shell and coordinator), lane F (red team). Built against Core v2 at c07c036. None of these blocks P15-E; each has a local workaround in `Packages/StarlingChaining`.

## 1. Core: the policy's items for a send it allowed

**What.** `OutboxObserver` gets `PolicyDecision`, and `.allow` carries no items, so "What left your phone" cannot list a send the policy allowed without a sheet unless the observer computes the items itself. Either of these, preferred first:

```swift
// a) PolicyEngine can say what a message discloses (lane G's engine already has it).
public protocol PolicyEngine: Sendable {
    func evaluate(_ message: OutboundMessage) async -> PolicyDecision
    func disclosure(for message: OutboundMessage) async throws -> Disclosure
}
// b) Outbox passes the disclosure it was judged on, for allow as well as needsConsent.
public protocol OutboxObserver: Sendable {
    func outbox(didSend envelope: Envelope, context: OutboundContext, decision: PolicyDecision, disclosed: [DisclosedItem]) async
}
```

**Why.** ADR 0011 decision 5: the audit uses the policy's items so it cannot disagree with consent. Test: `EgressRecorderTests.aSendAllowedWithoutASheetRecordsThePolicysItems`.

**Meanwhile.** `EgressRecorder` takes a `DisclosedItemsForSend` function; the app passes `DeterministicPolicyEngine.disclosure(for:)`'s items. The tests depend on StarlingPolicy (test-only) to wire exactly that.

## 2. Core: keep a friend's `chainedFrom` hint on the interaction

**What.** An optional, local-only field set by the coordinator from `SkillEvent.incoming(..., chainedFrom:)` after `IncomingChain.timelineParent` accepts it:

```swift
// Interaction
public private(set) var friendChainHint: ConversationID?   // never a ChainLink; grouping only
```

**Why.** ADR 0012 decision 6 lets the receiver group a friend's chained request on the plan's timeline, but `Interaction` has nowhere to keep the hint, and a `ChainLink` records the owner's own opt-in, so it must not be used. Test: `PlanTimelineTests.aFriendsChainedRequestIsGroupedButMarkedAsTheirs`.

**Meanwhile.** `PlanTimeline(for:in:registry:friendHints:)` takes a map from invitee interaction to hint, which lane A would persist beside the store.

## 3. Lifecycle contract: who applies `.started` for an initiator

`SwapPhotosService.start` emits `.lifecycle(id, .started)` and then its question. If lane A's coordinator applies `.started` itself when it calls `start`, the service's copy is an `InvalidTransition` (harmless, but noisy). Please settle it in ADR 0011 so every skill does the same; Swap photos will follow.

Show a waiting after-plan-ends link as the plan's "Photos after" chip, not under In progress.

6. Plan detail: `PlanTimeline` and its `whatLeft`; add hand-offs (Add to Calendar) as rendered rows.
7. Swap photos question: present `SwapPhotosPicker` and pass its `OwnerAnswer` to the service. Swap photos needs no Info.plist purpose string (ADR 0242).

## 5. Lane F: scenarios to cover

- A peer's envelope with `chainedFrom` naming a plan it was not in, a conversation that never became a plan, or a real plan: expect at most an invitee interaction, never a start, picker, permission, or schedule.
- A chained skill's service that omits or forges `chainedFrom`: expect `chain.chained_from_mismatch` denial and no egress record.
- A Swap photos offer with extra issues, a count over 24, or from someone outside the plan: expect it dropped.

## 6. Threat model additions

- `chainedFrom` is peer-controlled; it only groups on the timeline (ADR 0240 decision 7).
- Swap photos sends a photo count under the photos topic; no photo bytes travel in Phase 1.5 (ADR 0242).
