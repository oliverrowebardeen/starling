## Open finding

[#76](https://github.com/oliverrowebardeen/starling-ios/issues/76), lane B:
DownForService removes a delivery entry immediately after enqueueing its final
scheduled resend. If the per-friend worker is still sending the previous
proposal, it later drops that final queued job because the entry is gone.
The test holds the third proposal in willSend, releases it while the owner
window is still open, and observes three proposals instead of four. Only this
count expectation is marked known. The issue contains the command and exact
schedule. No reliable privacy inference is asserted from this failure alone.
