### Fixture and observation rules

- Use `Simulation(security: .secureChannel)`, the real service, Outbox, Inbox,
  policy, consent, and a shared ConversationLedger per phone. A, B, and C hold
  the same confirmed plan P at revision r; each phone retains its own local
  Plan ID and the shared origin conversation. X is a paired friend outside P; N
  is a friend of the suggester A only. A separate plan Q and an ended plan
  provide cross-plan controls. Pairing identity is authoritative, not a roster
  field, nickname, or `Envelope.sender` claim.
- Start legitimate suggestions with the owner's tap, in a fresh interaction and
  conversation. Record every phone's stored plan, lifecycle events, consent IDs,
  permission/model calls, audit entries, and decoded outgoing messages. Check
  all peers' final snapshots, including ID, origin, revision, terms, and roster.
  A local Plan value is not itself proof of peer authorization or agreement.
- For semantic replay, resend old terms in a fresh message with a valid new
  sequence through the attacker's Outbox. Also replay original authenticated
  bytes to cover the channel boundary. This distinguishes service validation
  from a replay that Inbox alone drops.
- Use injected service clocks and explicit suspension points for deadlines and
  races. Wait for registered timers and handled inputs before advancing time.
  Compare full decline and silence transcripts at the same virtual deadlines,
  not host elapsed time. Observe sender, recipient, body, parent, mode, per-friend
  sequence progression, and send schedule. Normalize only fresh random IDs with
  a consistent mapping; preserve their references and all roster/value fields.
- No-send assertions need a processing barrier or a drained virtual deadline,
  plus a legitimate subsequent request that proves the adapter is live.
  Condition waits use `P15.eventually` with the ADR 0257 120-second
  SuspendingClock budget. A fixed short sleep is not an absence proof.
- Exercise early replies with an explicit post-transport `didSend` observer
  hold, as in issue #105. Separate correct correlation from eventual recovery:
  retries may recover lost delivery, but must not conceal a genuine answer
  discarded before the service records its outgoing message ID. Never advance
  a clock to make that particular assertion pass.
- Recreate services and persisted state for restart cases. Through the app,
  reopen the actual disk stores. Retaining Simulation's secure connection does
  not establish process-crash or radio-recovery behavior.
